# Admin Dashboard

Single admin-only page at `/admin` that exposes catalog gaps, system-recipe quality issues, the latest LLM regen output, user management, and the audit log. This is the renamed and gated successor to the old `/curator` page; the old route 301-redirects to `/admin`.

## Why this exists

Catalog and system-recipe debt accumulates as users auto-create ingredients, the photo extractor falls back to stub rows (`fdcId: NULL`), and the LLM regen pipeline leaves recipes in JSONL files. Without a single admin surface listing the debt, an admin would have to write SQL or grep through `regen-failed.jsonl`. The dashboard is that surface, plus user management and an audit log of admin actions.

It is intentionally small: **a few sections, no charts, no destructive operations without an explicit confirm**. Every action calls an existing endpoint or one of the new admin endpoints.

## User Capabilities

- An admin (see [Roles & Authorization](./roles.md)) opens `/admin` from «Panel de admin» in Ajustes → «Cuenta y privacidad» (`/profile/ajustes`, PRO-1202). On desktop (`md+`) the left sidebar shows an **«Admin» block under the normal items**, only for admins: Catálogo (`/admin`), Recetas pendientes (`/admin/recetas`), Usuarios (`/admin/usuarios`), Invitaciones (`/admin/invitaciones`), Lista de espera (`/admin/lista-espera`), Opiniones (`/admin/opiniones`), Pregunta por WhatsApp (`/admin/pregunta-whatsapp`), Pregunta por correo (`/admin/pregunta-correo`), Uso de funciones (`/admin/funciones`) and Auditoría (`/admin/auditoria`), with the active one highlighted (`lib/adminNav.ts`). «Voz» (history of the retired voice mode, D-023) is left out of the menu and the mobile tabs but still opens at `/admin/voz`. Each area has its own heading and one-line intro; the four catalogue counts (ingredientes sin USDA, recetas con kcal=0, alérgenos sugeridos, archivos en regen) only show on Catálogo. Each area has its own URL (route `/admin/[[...seccion]]`; an unknown slug shows the catalogue). On desktop the page then keeps only the catalogue's seven gap tabs, wrapped so none hides off-screen; on mobile (no sidebar) every tab scrolls sideways and the non-catalogue ones navigate to their URL. E2E `admin-sidebar.spec.ts`. A non-admin lands on a 403 page that links back to `/menu`.
- The dashboard shows a counts header (ingredients sin USDA, recetas con kcal=0, alérgenos sugeridos, archivos en regen, usuarios suspendidos, acciones admin recientes).
- Pill-bar tabs jump between sections:
  - **Ingredientes sin USDA** — every ingredient with `fdcId IS NULL`. "Mapear a USDA" opens the re-map modal (`sections/RemapModal.tsx`, PRO-1125): the best entry comes **preselected** (the first with values; BEDCA first, then USDA Foundation, then SR Legacy) with **«Vale»** (applies it) and **«Buscar otra»** (the list, the manual search and "Estimar con Mimoia"). The manual search takes the automatic path: translated for USDA (`translateEsToEn`; English passes through) and searched in Spanish in BEDCA. Only ingredients: no FNDDS (survey dishes) and none of SR Legacy's dish categories (Restaurant Foods, Fast Foods, «Meals, Entrees, and Side Dishes», Baby Foods; `isIngredientCandidate`). Applying calls `PATCH /ingredients/:id/remap` with `{ fdcId }` or `{ bedcaId }` (BEDCA used to go through a PATCH that ignored the values), audited `ingredient.remap`, and the API **recomputes every recipe that uses the ingredient** (response `recipesRecomputed`; [Nutrition](./nutrition.md) → Recompute after a catalogue change). The Mimoia estimate recomputes them too.
  - **Sin nutrición** (API only, PRO-1125) — `GET /admin/ingredients/missing-nutrition`, read-only: the ingredients with no nutrition yet (a household's «Añadir», a stub) with the catalogue and household recipes that use them. Cocina fills them at night with `scripts/ingredientNutrition.ts`, see [Nutrition](./nutrition.md) → Filling missing nutrition.
  - **Pasillo «otros»** — `aisle === 'otros'` or `aisle IS NULL`. Inline `<select>`.
  - **Sin densidad** — heuristic: name matches density-relevant keywords AND `density IS NULL`. Inline numeric input.
  - **Sin peso por unidad** — `aisle === 'produce'` AND `unitWeight IS NULL` AND not bulk leafy. Inline numeric input.
  - **Alérgenos sugeridos** — rows where `inferAllergenTagsFromName(name)` produces tags not currently present. On top, **Sin sésamo** (PRO-1096, `sesameMissing` of `GET /admin/ingredient-gaps`): ingredients whose name says za'atar, dukkah, gomasio or halva (`PRO1096_SESAME_TERMS`) and whose stored tags lack `sesamo`, each with the published catalogue recipes that use it (linked) and how many household recipes do (a count, no names). Only shown when there is one; the row is fixed by hand (its «Aceptar» below, or by Cocina's approval). Below it, **Alérgenos descuadrados** (PRO-1118, `allergenMismatch`): the recipes whose stored `allergens` (what the ficha and Mimo read) differ from the union of their ingredients' `allergenTags` — catalogue ones by name with both lists, household ones as a count. Only shown when there is one; the boot step (`db:migrate`) logs the same count and writes nothing. Saving an ingredient's `allergenTags` (`PATCH /ingredients/:id`) recomputes and stores the `allergens` of every recipe that uses it, in the same transaction, with one `recipe.allergens_recompute` line per recipe in the audit log; ingredients and steps are never touched, and the saved menus re-check those recipes.
  - **Recetas de sistema con kcal=0** — system recipes (`authorId IS NULL`) whose `nutritionPerServing.kcal` is falsy. Lists which of their ingredients are still missing `fdcId`. Recipe name links to its detail page; admin fixes the upstream ingredient first, then re-saves the recipe to recompute.
  - **Output de regen** — collapsible list parsed from `apps/api/scripts/output/regen-failed.jsonl` and `regen-skipped.jsonl`.
  - **Usuarios** — see [User Management](./user-management.md). Sub-tab; lists, suspends, and generates reset password tokens.
  - **Auditoría** — see [Admin Audit Log](./admin-audit-log.md). Sub-tab; reverse-chronological feed of admin actions with filters by admin and action.
  - **Voz** — *historical since 2026-10-09 (D-023 retired OpenAI Realtime; Mimo's voice turns are ordinary assistant turns now)*: sessions list of the old voice-mode conversations (one row per session) with filters (user search + date range); click a row to drill into all turns of that session in chronological order, each turn tagged with the skill it invoked when applicable. Read-only — no mutations, no audit-log entries on read. Source: [Voice Mode](./voice-mode.md). Backed by `GET /admin/voice-transcripts/sessions` (grouped) and `GET /admin/voice-transcripts` (flat list with `?sessionId=` filter).
- Every mutation issued from the dashboard generates an entry in `admin_audit_log`.

- **Invitaciones** tab (PRO-27, `sections/InvitationsSection.tsx`): create a campaign invitation link — name (e.g. «familia», «amigos-padel», «post-linkedin»), optional max uses, optional expiry — via `POST /admin/invite-campaigns` (admin JWT, audited `invite_campaign.create`); the table lists every campaign (`GET /admin/invite-campaigns`) with its link `mimoia.com/i/<code>`, uses / max, expiry and, from `GET /admin/metrics` → `campaigns`, signups, activation and week 3 over the last 12 weeks, plus a «Sin campaña» row. Each campaign has **«Eliminar»** (2026-10-15): after a browser confirmation («¿Eliminar la campaña «X»? El enlace dejará de funcionar. Las N personas que entraron con él conservan su cuenta, pero se contarán en «Sin campaña».») it calls `DELETE /admin/invite-campaigns/:id` (admin JWT, audited `invite_campaign.delete` with name, code and uses; 404 if it doesn't exist). The link stops letting anyone in at once; accounts keep working and their `invite_campaign_id` goes null (FK `ON DELETE SET NULL`). See [Auth](./auth.md) → Closed beta
- **Recetas pendientes** (`/admin/recetas`, `sections/PendingRecipesSection.tsx` + `sections/CatalogImportPanel.tsx`, 2026-10-21): the catalogue drafts by batch, like a cookbook index (each batch a chapter with a side index at `lg+`, each recipe a line with dotted leaders to its origin · book · page, credit line, «Duda de alérgenos», audit issues in words, photo when there is one — «Haciendo su foto» until then —, «Detalles»). Per recipe «Publicar» (Miguel's OK + that recipe out; off while the audit holds it; without its photo yet it goes out by itself once the photo is made) and «Descartar» (his «no»; listed apart under «Descartadas», «Recuperar» takes it back); per batch «Publicar las aprobadas» with a confirmation when the rule leaves any. On top, «Subir un JSON»: upload or paste a Cocina batch file, «Comprobar» (problems in Spanish, what would be skipped), «Importar N recetas como borrador» in the background with its progress (the latest three imports, recipe by recipe). Every action audited. E2E `admin-recetas-pendientes.spec.ts` at 390×844 and 1440×900. See [Catalogue import](./catalog-import.md)
- **Opiniones** (`/admin/opiniones`, `sections/FeedbackSection.tsx`, 2026-10-15): what beta users sent from the «Opinión» button or told Mimo (web chat / WhatsApp), newest first, with who, channel, page and date; 7 / 30 / 90 days. See [Feedback](./feedback.md)
- **Pregunta por WhatsApp** (`/admin/pregunta-whatsapp`, PRO-1091, `sections/WhatsAppQuestionSection.tsx`): Customer Success's one question to a group of households. The question (the `{{1}}` of the `pregunta_unica` template in `WHATSAPP_TEMPLATES`, 10–900 characters), the group («Alta desde» / «Alta hasta», Madrid days, both included; «Días sin actividad», 0 = da igual), «Contar hogares» → «N hogares la recibirán» + «Fuera: … pidieron BAJA · … cuentas internas · … hogares de prueba · … sin WhatsApp · … ya la recibieron» and the template's name (or «Falta la plantilla «pregunta_unica» en WHATSAPP_TEMPLATES: no se puede enviar», button off). Any edit asks for a new count. «Enviar a N hogares» → a browser confirmation with the question → sent only if the count is still N («El recuento ha cambiado: ahora son M…» otherwise) → «Enviada a N hogares… Las respuestas llegan a Opiniones». Each household gets each question once; at most 200 per press. Below, «Preguntas enviadas» (text, date, households, failures, answers). Audited `whatsapp_question.send`. API `GET /admin/whatsapp-question`, `POST /admin/whatsapp-question/preview`, `POST /admin/whatsapp-question/send` (admin JWT). Rules in [WhatsApp](./whatsapp.md) → «Pregunta única por WhatsApp (Admin)». E2E `admin-whatsapp-question.spec.ts` (390×844 and the desktop menu)
- **Pregunta por correo** (`/admin/pregunta-correo`, PRO-1197, `sections/EmailQuestionSection.tsx`; approval `2026-11-11-cs-pregunta-hogares-que-lo-dejaron`, option A, Miguel 2026-11-12): one email from Miguel to the households that left the beta. Fixed in code: subject «¿Qué te faltó en Mimoia?», from «Miguel de Mimoia» on `EMAIL_FROM`'s address (hola@), reply-to the same address, the greeting «Hola, Nombre:» (the waitlist name, else a username that looks like a name, else «Hola:») and the footer «Te escribo porque tienes cuenta en la beta de Mimoia.». The body is the approved text, pasted in «Texto del correo» (80–4000 characters; a pasted «Hola{, Nombre}:» line is dropped, paragraphs tidied); the page shows the email as it will go. It is not kept in the repo (the approval is company data); it is kept in the audit entry. No logo, link or button. **Who:** households with no activity (usage events or a WhatsApp message) in 14 days and created at least 14 days ago; out, each counted under the first reason that applies: «activos» (including the newer ones), «con cuenta interna» (role admin or `ADMIN_EMAILS`), «de prueba» (a reserved test domain or `EMAIL_SINK_DOMAINS`), «con cuenta suspendida» (any member), «pidieron BAJA o «No, gracias»» (any member, on WhatsApp) and «ya lo recibieron». One person per household (the owner, else the earliest member), one email each (its own `to`, never CC). The page opens with the exact count («N hogares lo recibirán»), the «Fuera: …» line, the email as it goes out and one button «Pregunta por correo a N hogares» (off until the body is pasted) → a browser confirmation → sent only if the count is still N («El recuento ha cambiado: ahora son M…» otherwise; nothing goes out with 0 or without `RESEND_API_KEY`) → «Enviado a N hogares… Las respuestas llegan a hola@». **Never twice:** `email_question_sends` (unique email + household) is claimed before each send, so a second press, or a second admin, sends nothing; a failed send stays failed and is not retried. Afterwards «Ya enviado a N hogares (fecha)». One by one, 0.6 s apart (Resend's rate). Audited `email_question.send`. API `GET /admin/email-question` (count, reasons, what went out, the fixed parts of the email), `POST /admin/email-question/send` `{ body, expectedCount }` (admin JWT). Rules in `services/emailQuestion.ts` (tests `emailQuestion.test.ts`, `emailQuestion.smoke.ts`); migration 0111 (adds the table). E2E `admin-email-question.spec.ts` (390×844 and the desktop menu)
- **Newsletter** (`/admin/newsletter`, PRO-1123, D-176, `sections/NewsletterSection.tsx`): one issue at a time (the Friday's date, the next one prefilled; the last 12 as chips). Marketing's recommendation with «Empezar desde la recomendación»; «Tu carta» (Asunto, Preheader, Saludo, Titular, Carta, Despedida and the rest of the issue as JSON) with the placeholders `{nombre}`, `{receta}`, `{porque}` and a warning when there are none; «Guardar plantilla» (clears the proof and the schedule); «Ver vista previa» (3 real recipients, admins only); «Enviarme la prueba» (to the signed-in admin's own email, with their own case); «Programar para el viernes a las 9:00» only with the proof of the template saved that week, and «Desprogramar». Every action audited. Rules in [Newsletter](./newsletter.md) → «Editor en Admin». E2E `admin-newsletter.spec.ts` (390×844)
- **Lista de espera** (`/admin/lista-espera`, PRO-97, `sections/WaitlistAdminSection.tsx`):
  - **Inscritos**: en la lista, esperando, invitados, ya registrados, plus altas in 7 days, target-segment households and WhatsApp interest; **Por canal** (`?ref` source with counts). Both from `GET /admin/waitlist`.
  - **Tanda sugerida** (`GET /admin/waitlist/next-batch?size=20`, admin JWT only — the metrics token never sees names or emails): each person in invitation order (`suggestNextBatch`) with name, email, answers, channel, WhatsApp, «entra con quien le invitó» and «fuera del segmento». Size editable (1–200). «Quitar» takes someone out of this batch (they stay waiting; «volver a añadir» undoes it).
  - **«Invitar a estas N personas»** → a confirmation («¿Invitar a N personas?… No se puede deshacer.», «Sí, invitar y enviar el correo» / «Cancelar») → `POST /admin/waitlist/invite` with the remaining ids. The result says the batch number, how many were invited and the email counts; for anyone whose email wasn't sent (no Resend key, or a failure) it lists their one-time link to send by hand.
  - **Tandas**: per batch invitados, registrados, sin registrarse and de baja (`batches` of the report). «Activos» (using the app) per batch is not shown: the report doesn't link entries to accounts' activity.
  - E2E `waitlist-invite.spec.ts` at 1440×900 and 390×844.

## Scope vs My Recipes

The admin dashboard handles **system recipes only** (`authorId IS NULL`). User-created recipes are out of scope here — users curate their own recipes via «Mis recetas» in the Recetas tab (`/recipes/mias`) (see [My Recipes](./my-recipes.md)). The split is enforced server-side: every admin mutation that touches a recipe rejects with 400 if `authorId !== NULL`.

## Constraints

- `requireAdmin` middleware on all admin endpoints (server-side enforced — frontend gating is decoration). See [Roles & Authorization](./roles.md).
- The old `/curator` route is kept as a permanent client-side redirect to `/admin`. After 60 days the redirect can be removed; in the meantime old links still work.
- Same heuristics as before for ingredient gaps. Editorial design system tokens (cream `#FAF6EE`, ink `#1A1612`, terracotta `#C65D38`, parchment `#FFFEFA`, border `#DDD6C5`).
- No new dependencies. Spanish copy throughout. The dashboard is server-rendered via Next.js client components but every admin action does an explicit server-side `requireAdmin` check — no Next.js route-level gating only.

## Business metrics

`GET /admin/metrics?weeks=8` returns weekly active households, resolved weeks, signup cohorts and cost per active household from the cost ledger — admin JWT or the read-only `x-metrics-token`. Its `campaigns` block shows in the Invitaciones tab; otherwise no UI tab yet — see [Business Metrics & Cost Ledger](./metrics.md).

## WhatsApp conversation reviews

`GET /admin/assistant-reviews?limit=N` lists the daily conversation reviews (findings, stats, summary), newest first. `POST /admin/assistant-reviews/run { day?, notify? }` runs or re-runs one day. Both are admin-only; see [WhatsApp](./whatsapp.md) → Conversation reviewer agent. There is no UI tab yet.
