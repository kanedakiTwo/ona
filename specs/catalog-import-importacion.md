# Catalogue import · La importación por lotes

> Parte de [Catalogue import](./catalog-import.md) (la portada lista todas las partes): cómo funciona `apps/api/scripts/catalogImport.ts`, paso a paso.

## The import (`apps/api/scripts/catalogImport.ts`)

Run from a laptop with `DATABASE_URL` and `ANTHROPIC_API_KEY` (see the file header for every flag):

1. `import --dir=<folder> --origin=miguel|cocina --book="…" [--credit="…"] --batch=<id>` — a folder of page photos (`.jpg/.png/.webp`) or PDFs (split into pages with `pdftoppm`; page number from the file name or the PDF page). `--json=<file>` takes Cocina's batch file instead (hand-authored shape: ingredients by name with `qty`/`unit`, steps, optional `source` for the file or per recipe). `--credit` is the ficha's line, as it must read («Receta de la Yaya»); in a JSON file `source.credit` goes for the file or per recipe — the recipe's wins, then the file's, then `--credit`; blank = none (`draftsFromCocinaJson`). `--dry-run` saves nothing.
2. Per recipe, in order (`services/catalogImport.ts`, orchestration with injected AI and database):
   - **reading**: the photo extractor that `POST /recipes/extract-from-image` uses (`AnthropicProvider.extractRecipe`);
   - **duplicates**: against every catalogue recipe (published and drafts) and the batch itself — same dish when the significant words match (accents, plurals, order and filler words aside: «Tortilla de patata» = «Tortilla de patatas») or the names are ≤ 2 letters apart → skipped, «ya está: …»;
   - **bases** (PRO-373): a recipe of the file may say which bases it uses, `bases: [{ name, servings }]` (servings of the base for the recipe's own `servings`; at most 10). Each name is looked up — accents, case and spacing aside — first among the recipes of the same batch already saved (or found repeated in the catalogue), then in the catalogue, drafts included (`findCatalogRecipeByName`, a published one first). The batch is imported **with the recipes another one uses as a base first** (`basesFirst`, file order otherwise), so a dish finds its base even when the file lists it later. A name that isn't found **rejects the recipe** before any AI is paid: reason `bases`, «usa una base que no está en el catálogo ni en la tanda», detail «sin la base en el catálogo ni en la tanda: <nombre>». The servings scale with the recipe to the house's 4 and are saved in `recipe_bases` with the draft. A base itself is a recipe with `base` in its `tags` (see [Recipes](./recipes.md) → Bases de batch cooking);
   - **frying / confit oil** (`markCookingMediumLines`, PRO-195, before scaling): a fat line (aceite, manteca, mantequilla, grasa) that is only the frying or confit medium gets a note starting «para freír…» / «para confitar…» («abundante para freír» → «para freír; abundante», «de freír» → «para freír», a name «aceite de girasol para freír» → name «aceite de girasol» + that note), so nutrition counts only what the food absorbs (15 % / 25 %, see [Nutrition](./nutrition.md)) and the reviewer accepts the amount. A mixed line («540 ml — 40 ml para el sofrito y el resto para freír») is split into two lines (40 ml «para el sofrito», 500 ml «para freír»); a mixed note it can't read (no amount, units that don't convert) is left as it is. The rewrite links each oil line to its own step;
   - **quantities for 4** (`scaleToHouseServings`; «al gusto» and «pizca» don't scale);
   - **steps rewritten in the house's own words** plus labels, one Claude Opus 5.5 call (`services/catalogRewriter.ts`, `CLAUDE_MODEL`): meal, season, course, dish type, main protein, techniques, cuisine, active and total time (for someone who cooks at home with ease; prep done while the oven or the pot go by themselves counted once — PRO-284), difficulty, allergen doubt, a short tip, and the storage seals (`freezable`, `fridgeDays`: see Storage seals below). The book's steps are read to understand the technique and **never saved**;
   - **a batch Cocina already rewrote** (PRO-1097, D-150 option C: the rewrite and the labels are done by Cocina — Claude Code in the office, on the subscription — so the import doesn't spend from Mimoia's API credits): a batch file with `"reescrita": true` (file level) brings, per recipe, the house steps as `{ text, durationMin?, temperature?, technique?, ingredientRefs? }` (indexes from 0 into its ingredient list) and the labels the rewriter would give, at the recipe's top level: `course` (`starter | main | dessert`), `dishType`, `protein`, `techniques`, `cuisine`, `activeTime`, `totalTime`, `allergenDoubt`, `allergenNote`, `tips` (`catalogRewriteLabelsSchema` in `@ona/shared`, part of `cocinaRecipeSchema`), plus its own `difficulty`, `meals`, `seasons`, `freezable` and `fridgeDays`. A bad value is a problem in Spanish like any other field; the check warns that the batch comes rewritten; the command checks it with the same schema before importing. The import then **makes no call to the model** (no `catalog_import_rewrite` in `cost_events`): the steps and labels go through the same path as the rewriter's answer (`rewriteFromBatch` → tags, times, storage seals), and the phrase check and the stray-words retry, which compare against a source text the batch doesn't carry, are skipped. Everything else stays: duplicates, frying oil, quantities for 4 (write the steps for 4: quantities are scaled, step texts aren't), ingredient matching, audit, reviewer (it still rejects a step naming an unlisted ingredient), nutrition, allergens and the photo. Without `reescrita` (or `false`) those step fields and labels are ignored and the rewriter is called as before;
   - **phrase check**: a step (or the tip) that keeps **7 words in a row** of the source is rewritten once more, told which phrases to avoid; if it still copies, the recipe is rejected («copia del libro») and nothing is saved;
   - **words that read as an unlisted ingredient** (2026-10-25: 11 of the 109 «Jerusalem» recipes lost to the reviewer for the rewrite's own words — «saca la carne» of an aubergine, «el hueso» of a peach, «la yema de los dedos», «galletas» in a cookie recipe): when the rewrite names meat, fish, shellfish or an allergen that neither the ingredients nor the source steps account for (`strayDietWords`, the reviewer's own word list `unlistedDietMentions`), it is rewritten once more, told which words to avoid; a second try that copies the source is dropped and the first goes on to the reviewer. A word the source already uses isn't retried: the reviewer rejects it as before. Since PRO-401 the flesh, the stone and the dish of the title read right and aren't retried;
   - **ingredients**: matched to the catalogue (token match → AI → a new ingredient is created automatically, as in every import); an ingredient that can't be matched nor created rejects the recipe;
   - **audit** (`auditCatalogRecipe`: no steps, ≤ 2 ingredients, protein or starch per serving out of range) — the issues travel with the draft;
   - **reviewer** (`recipeLint`, strict, inside `persistRecipe`), **nutrition** and **allergens** (computed from the ingredients on save); right after the save the total follows the PRO-284 overlap rule (`applyCatalogTimeTrim`, see [Menus](./menus.md) → Time to cook). Reviewer errors reject the recipe with its messages. Since PRO-289 (after `cocina-01` lost 26 of 32 recipes to false positives) the reviewer reads whole words, doesn't ask for water and salt, and takes sofrito vegetables and milk at a dressing amount; since PRO-268 it also rejects a step that names meat, fish, shellfish or an allergen the ingredients don't account for (`STEP_DIET_INGREDIENT_NOT_LISTED`) ([Recipe Quality](./recipe-quality.md));
   - **saved as `draft`**: the row is created as a draft first and then filled, so it is never visible, not even for a moment. Labels go to `tags` (dish type, cuisine) and hidden `internal_tags` (`catalogo-tanda`, `tipo:`, `proteina:`, `tecnica:`, `cocina:`, `alergenos:duda`); `prepTime` = active time, `cookTime` = the rest of the total.
   - The source is kept in `recipes.catalog_source` (origin, book, page, file, credit, batch — **never its text**; `catalogSourceRecord`), with the audit issues and the allergen doubt; `recipes.import_batch` holds the batch id.
   - **The link to the original** (PRO-1015): a batch file's `source.url` (the creator's post or video; per recipe or for the file, the recipe's wins) goes to `recipes.source_url` with its type (YouTube or article), so the ficha links it — «Ver fuente» and the credit line ([Recipes](./recipes.md), PRO-1075). Only http(s) addresses; anything else is a problem in Spanish («el enlace al original (source.url) no es un enlace»). Before this, the route schema dropped `url` and every imported creator recipe came out without its link.
   - **La receta del día** (PRO-1099, [Recipe of the day](./recipe-of-the-day.md)): a recipe of the batch file may bring `featuredOn: "AAAA-MM-DD"`, the day it is the recipe of the day (`recipes.featured_on`, unique, migration 0106). A value that isn't a real day, or two recipes of the file on the same day, are problems in Spanish like any other field; a day another recipe already holds rejects the recipe («El … ya tiene receta del día («…»)…»). It is saved with the draft row and counts only once the recipe is published (D-164.1).
   - **Storage seals** (PRO-372, `recipes.freezable` / `recipes.fridge_days`, shown on the ficha — see [Recipes](./recipes.md)): Cocina's batch file may bring `freezable` (true/false) and `fridgeDays` (whole days, 1–30) per recipe (`cocinaRecipeSchema`; a bad value is a problem in Spanish like any other field). What the batch says wins, key by key; what it leaves out comes from the house rewrite, which always answers both (`true`/`false`/`null` and 1–5 days or `null` when unsure; `storageFrom`, `cleanFridgeDays`). Saved with the draft row (`persistCatalogDraft`).
   - **Essential and secondary ingredients** («Cocinar ahora», PRO-1105, see [Cook now](./cook-now.md)): each ingredient of the batch file may bring `imprescindible` (true → `essential`, false → `secondary`; absent = the automatic rule decides) and `sustitutos` (up to 5 catalogue ingredient names that can stand in for it). The substitutes are matched to the catalogue by token match (`findIngredientIds` → `findCatalogIngredientIds`, only when the recipe has any; it never creates an ingredient); a name that doesn't match is dropped and the command prints «sustituto sin casar: <nombre> (<receta>)». Saved as `recipe_ingredients.role` and `substitute_ingredient_ids`. A wrong type is a problem in Spanish like any other field.
3. One failure never stops the batch; the command prints ✓ / = (duplicate) / ✗ (reason) per recipe and a summary with the allergen doubts.
