# Catalogue import by batches and «deseos del catálogo»

How Mimoia's recipe catalogue grows from ~80 to 1.000 recipes (D-065, PRO-154): recipes come in by batches from Miguel's books, his mother's recipe book or what Cocina finds or writes, wait as **drafts** nobody sees, and are **published** by a rule. Alongside, the catalogue keeps a list of **dishes households want and we don't have** («deseos del catálogo») so Cocina knows what to bring next.

## User Capabilities

- **Households never see a draft.** A catalogue recipe in `draft` is not in `/recipes` (signed in or out), doesn't open by link (404, same as a missing recipe), the menu never picks it and Mimo never offers it. Once published it behaves like any other catalogue recipe.
- **An admin opens a draft by its link** (`/recipes/<id>` with an admin account): that is how Miguel reviews every recipe of a Cocina batch.
- **Admin → «Recetas pendientes»** (`/admin/recetas`): every catalogue draft, by batch, with «Publicar» and «Descartar» per recipe and the import of a new Cocina batch file — the web side of `sample`, `review`, `publish` and `import --json` (see below).
- **The ficha says where it comes from** (D-067): a published recipe shows one line under its title — the batch's `credit` as written («Receta de la Yaya», «Inspirada en una receta de <autor>, «<libro>»»); without a credit, Miguel's sources read «Inspirada en <book>» and Cocina's show nothing. See [Recipes](./recipes.md).
- **Every recipe comes out with its photo** (Miguel, 2026-10-21: «debería generarse antes de que nadie pudiera acceder»). The API makes the house photo ([Recipe Images](./recipe-images.md)) of every catalogue draft right after it's saved (`catalogPhotos.ts`), and **nothing is published without one**: a recipe the rule allows but whose photo isn't made yet waits as «sin_foto» and goes out **by itself** the moment its photo is saved — if publishing was asked for (`publish`, «Publicar», «Publicar las aprobadas») and the rule still allows it. A published recipe still without a photo (the checker turned it down, or one published before this rule) gets one too: the same job does those first, and the first menu or visit that shows it asks for it as well (`catalogImageOnDemand.ts`, the safety net).
- **Admin → Catálogo → «Deseos del catálogo»**: the dishes households asked for that we don't have, most-asked first, with how many households ask and where it came from («favoritos del alta», «menú sin acierto», «petición a Mimo», «Me encanta»). Filters: «Pendientes», «Ya cubiertos» (with a link to the recipe that covers it), «Todos». No names, no emails.

## The import (`apps/api/scripts/catalogImport.ts`)

Run from a laptop with `DATABASE_URL` and `ANTHROPIC_API_KEY` (see the file header for every flag):

1. `import --dir=<folder> --origin=miguel|cocina --book="…" [--credit="…"] --batch=<id>` — a folder of page photos (`.jpg/.png/.webp`) or PDFs (split into pages with `pdftoppm`; page number from the file name or the PDF page). `--json=<file>` takes Cocina's batch file instead (hand-authored shape: ingredients by name with `qty`/`unit`, steps, optional `source` for the file or per recipe). `--credit` is the ficha's line, as it must read («Receta de la Yaya»); in a JSON file `source.credit` goes for the file or per recipe — the recipe's wins, then the file's, then `--credit`; blank = none (`draftsFromCocinaJson`). `--dry-run` saves nothing.
2. Per recipe, in order (`services/catalogImport.ts`, orchestration with injected AI and database):
   - **reading**: the photo extractor that `POST /recipes/extract-from-image` uses (`AnthropicProvider.extractRecipe`);
   - **duplicates**: against every catalogue recipe (published and drafts) and the batch itself — same dish when the significant words match (accents, plurals, order and filler words aside: «Tortilla de patata» = «Tortilla de patatas») or the names are ≤ 2 letters apart → skipped, «ya está: …»;
   - **frying / confit oil** (`markCookingMediumLines`, PRO-195, before scaling): a fat line (aceite, manteca, mantequilla, grasa) that is only the frying or confit medium gets a note starting «para freír…» / «para confitar…» («abundante para freír» → «para freír; abundante», «de freír» → «para freír», a name «aceite de girasol para freír» → name «aceite de girasol» + that note), so nutrition counts only what the food absorbs (15 % / 25 %, see [Nutrition](./nutrition.md)) and the reviewer accepts the amount. A mixed line («540 ml — 40 ml para el sofrito y el resto para freír») is split into two lines (40 ml «para el sofrito», 500 ml «para freír»); a mixed note it can't read (no amount, units that don't convert) is left as it is. The rewrite links each oil line to its own step;
   - **quantities for 4** (`scaleToHouseServings`; «al gusto» and «pizca» don't scale);
   - **steps rewritten in the house's own words** plus labels, one Claude Opus 5.5 call (`services/catalogRewriter.ts`, `CLAUDE_MODEL`): meal, season, course, dish type, main protein, techniques, cuisine, active and total time (for someone who cooks at home with ease; prep done while the oven or the pot go by themselves counted once — PRO-284), difficulty, allergen doubt, a short tip, and the storage seals (`freezable`, `fridgeDays`: see Storage seals below). The book's steps are read to understand the technique and **never saved**;
   - **phrase check**: a step (or the tip) that keeps **7 words in a row** of the source is rewritten once more, told which phrases to avoid; if it still copies, the recipe is rejected («copia del libro») and nothing is saved;
   - **words that read as an unlisted ingredient** (2026-10-25: 11 of the 109 «Jerusalem» recipes lost to the reviewer for the rewrite's own words — «saca la carne» of an aubergine, «el hueso» of a peach, «la yema de los dedos», «galletas» in a cookie recipe): when the rewrite names meat, fish, shellfish or an allergen that neither the ingredients nor the source steps account for (`strayDietWords`, the reviewer's own word list `unlistedDietMentions`), it is rewritten once more, told which words to avoid; a second try that copies the source is dropped and the first goes on to the reviewer. A word the source already uses isn't retried: the reviewer rejects it as before;
   - **ingredients**: matched to the catalogue (token match → AI → a new ingredient is created automatically, as in every import); an ingredient that can't be matched nor created rejects the recipe;
   - **audit** (`auditCatalogRecipe`: no steps, ≤ 2 ingredients, protein or starch per serving out of range) — the issues travel with the draft;
   - **reviewer** (`recipeLint`, strict, inside `persistRecipe`), **nutrition** and **allergens** (computed from the ingredients on save); right after the save the total follows the PRO-284 overlap rule (`applyCatalogTimeTrim`, see [Menus](./menus.md) → Time to cook). Reviewer errors reject the recipe with its messages. Since PRO-289 (after `cocina-01` lost 26 of 32 recipes to false positives) the reviewer reads whole words, doesn't ask for water and salt, and takes sofrito vegetables and milk at a dressing amount; since PRO-268 it also rejects a step that names meat, fish, shellfish or an allergen the ingredients don't account for (`STEP_DIET_INGREDIENT_NOT_LISTED`) ([Recipe Quality](./recipe-quality.md));
   - **saved as `draft`**: the row is created as a draft first and then filled, so it is never visible, not even for a moment. Labels go to `tags` (dish type, cuisine) and hidden `internal_tags` (`catalogo-tanda`, `tipo:`, `proteina:`, `tecnica:`, `cocina:`, `alergenos:duda`); `prepTime` = active time, `cookTime` = the rest of the total.
   - The source is kept in `recipes.catalog_source` (origin, book, page, file, credit, batch — **never its text**; `catalogSourceRecord`), with the audit issues and the allergen doubt; `recipes.import_batch` holds the batch id.
   - **Storage seals** (PRO-372, `recipes.freezable` / `recipes.fridge_days`, shown on the ficha — see [Recipes](./recipes.md)): Cocina's batch file may bring `freezable` (true/false) and `fridgeDays` (whole days, 1–30) per recipe (`cocinaRecipeSchema`; a bad value is a problem in Spanish like any other field). What the batch says wins, key by key; what it leaves out comes from the house rewrite, which always answers both (`true`/`false`/`null` and 1–5 days or `null` when unsure; `storageFrom`, `cleanFridgeDays`). Saved with the draft row (`persistCatalogDraft`).
3. One failure never stops the batch; the command prints ✓ / = (duplicate) / ✗ (reason) per recipe and a summary with the allergen doubts.

## Publishing (rule of Miguel, 2026-10-16)

- `status --batch=…` — what's in the batch and what `publish` would do.
- **Miguel's sources** (`--origin=miguel`: his books, his mother's recipe book) are published **without going through him** when they pass the audit: `publish --batch=…`.
- **Cocina's** (`--origin=cocina`: found or written by Cocina) are **all** seen by Miguel (D-099, PRO-290; until 2026-10-20 it was one in ten): `sample --batch=…` (`listForReview`) prints the link of **every** draft of the batch (admin account), the ones with an allergen doubt first, with the verdict already given if any; running it again never clears a verdict. Miguel's answer goes in with `review --ok=<ids> --no=<ids>`, recipe by recipe; then `publish --batch=…`.
- `publish` (`planBatchPublish`) holds: a recipe Miguel turned down («rechazada»); any recipe with audit issues («auditoria»); every Cocina recipe without his OK («sin_revisar»); and, last, one whose photo isn't made yet («sin_foto»). Cocina's go out **one by one**: only the ones with `reviewOk: true`, so a half-reviewed batch publishes its OKs and the rest wait; a «no» holds only that recipe. The «sin_foto» ones are marked `publishWhenPhoto` and go out by themselves when the photo lands (the command prints «N esperan su foto…»). `--dry-run` only prints.
- Publishing closes the wishes the new recipes cover (`markWishesCovered` → `cubierto`, pointing at the recipe).

## Admin page «Recetas pendientes» (`/admin/recetas`)

What the command does with `sample`, `review`, `publish` and `import --json`, from the web, with the same rule (D-099: Miguel sees and approves every Cocina recipe one by one; nothing goes out without his click). Laid out like a cookbook index (the page used to pick recipes from two books for the catalogue): each batch a chapter (newest first, a side index at `lg+`, chips on mobile), each recipe a line with dotted leaders to where it comes from.

- **The list** (`GET /admin/catalog-drafts`, `loadCatalogDrafts` → `buildDraftsView`): per batch, its origin, how many are still to decide, published and discarded. Per recipe: photo if it has one, name linking to `/recipes/<id>`, origin · book · page, the credit line it will show (D-067), «Duda de alérgenos», each audit issue in words («Auditoría: sin pasos»), «Ya dijiste que sí» when he OK'd it from the command, «Haciendo su foto» while it has none (or «Sale en cuanto tenga su foto» once publishing was asked for); «Detalles» opens servings, total time, steps, difficulty, ingredient names, tags and the tip. Allergen doubts first, then in import order. Search (dish or ingredient) and «Solo con dudas».
- **«Publicar»** (`POST /admin/catalog-drafts/:id/publish`, `publishCatalogDraft`): his OK (`reviewOk: true`) and that recipe out, in one transaction with the audit row; closes the wishes it covers. A recipe with audit issues can't go out (button off, «No se puede publicar mientras la auditoría vea algo»; the API answers 409 `AUDIT_HOLD` with the issues). Without its photo yet, the OK is kept with `publishWhenPhoto` (audited with `waitingPhoto: true`), the answer is `{ published: false, waitingPhoto: true }` and the page says «saldrá en cuanto tenga su foto (unos minutos)»; it stays on the list until it goes out.
- **«Descartar»** (`…/discard`): his «no» (`reviewOk: false`). The draft stays hidden for good, listed under «Descartadas (N)» in its batch, so a new import of the same file skips it as repeated. **«Recuperar»** (`…/restore`) takes the verdict back.
- **«Publicar las aprobadas»** per batch (`POST /admin/catalog-batches/:batch/publish`, `publishBatch` — the same helper `publish --batch=…` uses), only when the rule leaves any: Cocina's OK'd but not out yet, or Miguel's sources that pass the audit («Publicar las N que pasan la auditoría»), counting the ones whose photo is still being made. Confirmation first; the notice says how many wait for their photo and will go out by themselves.
- **Import a batch file** («Subir un JSON»): choose the file or paste it, and a batch name (suggested from the file name without the date: `2026-10-20-cocina-01.json` → `cocina-01`). «Comprobar» checks it in the browser with the shared schema (`cocinaBatchFileSchema` in `@ona/shared`) and lists every problem in Spanish with where it is («Receta 2 («Bizcocho»), ingrediente 2 («huevo»): la unidad «gr» no vale; usa g, ml, u, cda, cdita, pizca o al_gusto.»; a JSON syntax error says the line and column); then `POST /admin/catalog-import/check` says what an import would skip (`previewDuplicates`: already in the catalogue, drafts included, or twice in the file) and warns when the file says it is from Miguel's sources (those can go out without his review). «Importar N recetas como borrador» → `POST /admin/catalog-import/jobs` answers 202 at once and the API imports in the background (`catalogImportJobs.ts`): same pipeline as `import --json=… --origin=cocina` (`draftsFromCocinaJson` with origin `cocina` unless the file says otherwise, file name as `source.file`). Progress lives in `catalog_import_jobs` (migration 0090: batch, origin, file name, status `running | done | failed | interrupted`, done of total, one outcome per recipe — in draft, repeated with what it repeats, rejected with the reason — never the file's text). The page polls every 3 s while one runs; drafts appear in the list as they arrive, and each one's photo starts as soon as it's saved. The latest three imports show below (finished ones as one line that opens recipe by recipe).

## Menú del mes (PRO-378)

Once a month Cocina writes a week of published catalogue dishes for households to copy into theirs ([Menus](./menus.md) → «Menú del mes»).
- **The file** (Cocina keeps them in its «menus-del-mes» folder; example with invented dishes: `apps/api/src/tests/fixtures/menu-del-mes-inventado.json`): `{ "month": "2026-11", "title"?: "…", "days": { "lunes": { "comida": [...], "cena": [...] }, … } }`. Days `lunes`…`domingo`, meals `desayuno`, `comida`, `merienda`, `cena` (accents and case aside), up to 3 dishes per meal; a dish is a published catalogue recipe's id or its exact name. Without `title`: «Menú de noviembre».
- **The import**: `POST /admin/month-menus` `{ file }` (admin JWT; `importMonthMenu`). One per month: importing the same month again replaces it (200; new → 201). Refused with 422 `{ problems }`, every problem in Spanish with its day and meal, when the file is malformed, a dish isn't in the published catalogue (drafts and retired recipes don't count), or the week breaks Cocina's rules (`checkMonthMenuRules`, with `weekRules.ts`): **at least 5 days with lunch and dinner**; **no fish or seafood at lunch and dinner the same day** (`isFishDish`: «Martes: pescado en la comida («…») y en la cena («…»); el mismo día, solo en una.»); **nothing over 45 min from Monday to Friday** (`recipeTotalMinutes`; weekends free).
- Saved in `catalog_collections` (`kind = 'menu_mes'`, `month`, `week`, `created_by`), migration 0099.

## Deseos del catálogo

- **What counts as «we don't have it»** (`catalogCoversDish`): a dish is covered when every significant word of it is in one published recipe's name («carbonara» ⊂ «Espaguetis a la carbonara»). One shared word isn't enough («pastel de carne» is not covered by «Menestra de verduras con carne»). An answer like «cremas y sopas» means either, so a crema *or* a sopa covers it.
- **One wish per dish** (`dish_key`: accents, plurals, order and filler words aside) — singular and plural share the root since PRO-203 (`stem()` in `recipeLint.ts`: «sopa»/«sopas» → «sop», so «sopas» is covered by «Sopa miso»; wishes saved before keep their old key, so a vote for «sopa» may open a second wish next to an older «sopa» one) and **one vote per household** per source (the user's own id when they have no household); the count is distinct households.
- **Sources today**: `alta` — the favourite dishes of the sign-up (web and WhatsApp, both through `saveOnboarding`) that the catalogue doesn't cover; best effort, never breaks the sign-up. `evaluador` (PRO-155) — favourite dishes the menu evaluator finds «no está en el catálogo» after each generated week (`services/menuFit.ts`). `mimo` is accepted by `recordCatalogWish` for that caller.
- `GET /admin/catalog-wishes?status=abierto|cubierto|descartado|todos&limit=` — admin JWT or `x-metrics-token` (Cocina's read). Returns dish, households, sources, status, covering recipe and dates; never who asked. The dish is free text from a registered user, accepted as a dish name; with the token it is cut to 80 characters (`catalogWishes.test.ts`).

## Constraints

- Only catalogue recipes (`author_id IS NULL`) can be drafts; user recipes are always `published`. `recipes.status` is checked at the database (`'draft' | 'published'`, default `published`, migration 0058).
- Every query that serves recipes to a household goes through `visibleRecipeWhere`, which now also requires `published`; `GET /recipes` filters it explicitly; `GET /recipes/:id` and `POST /recipes/:id/copy` answer 404 for a draft unless the caller is an admin.
- Catalogue photos are made only in the API (the photo volume is there; the command can't write it): 30 s after boot, every 10 minutes, and at once when the page imports a draft or asks to publish one without a photo. One at a time, in this order: published without a photo, drafts waiting to go out, the other drafts; never a discarded draft. Drafts imported by the command get theirs on the next pass (≤ 10 minutes). Each recipe is asked for at most once every 6 hours per API process, shared by the job and the on-demand path (`claimCatalogPhoto`), so a photo the checker turned down twice isn't paid again on every pass or view, and the two never pay twice for one photo; a failed call (network) is retried on the next pass. Only recipes with no image at all; a no-op without an image provider or under tests. Cost lands on Mimoia (no author).
- **Storage seals for the catalogue that already exists** (PRO-372, `catalogStorageLabels.ts`): in the API, 60 s after boot and every hour, the catalogue recipes (`author_id IS NULL`, drafts included) missing `freezable` or `fridgeDays` are labelled **20 at a time**, one call per 20 with the rewriter's model (name + ingredient names in, `{ n, freezable, fridgeDays }` out; cost `catalog_storage_labels` on Mimoia). Only empty columns are written (`COALESCE`), so Cocina's values are never overwritten, and users' recipes are never touched. A recipe the model is unsure about stays without the seal and isn't asked again until the API restarts; a failed call stops the pass and its 20 are asked again on the next one. A no-op without `ANTHROPIC_API_KEY` or under tests.
- A draft whose photo the checker keeps turning down stays «sin_foto» (it never goes out photo-less); it's tried again after 6 hours or a restart. When the photo lands, `publishIfWaitingForPhoto` re-checks the rule: a «no» or an audit issue given meanwhile keeps it in (and clears the flag).
- Never put a book's text in tests, fixtures or the database: tests use invented sentences.
- Of `catalog_source`, only the credit line leaves the public API (`sourceCredit` on `GET /recipes/:id`, via `catalogSourceCredit`); the file, batch, audit notes and review state stay inside — only the admin page (admin JWT) sees them, and never any source text (there is none stored).
- One import at a time per API process (409 `IMPORT_RUNNING`, also when another process left a job `running`). A job still `running` when the API boots died with the previous process (a deploy) and is marked `interrupted`: upload the same file again and the recipes already in are skipped as repeated. Without `ANTHROPIC_API_KEY` the import answers 503 `NO_AI_KEY` and nothing starts. The import's AI is billed as a system job (like the command), not to the admin who clicked.
- The import routes read their own body, up to 2 MB (the global JSON limit is 100 KB), so the router is mounted before `express.json()`; over it → 413 «demasiado grande». A batch holds at most 200 recipes.
- Every route is admin JWT only (`authMiddleware` + `requireAdmin`); the metrics read token opens none. Every change is audited: `catalog_draft.publish|discard|restore`, `catalog_batch.publish`, `catalog_import.start` ([Admin Audit Log](./admin-audit-log.md)).
- The audit issues shown and used to hold a recipe are the ones saved at import time (`catalog_source.auditIssues`), as for the command: a recipe imported before an audit rule changed keeps the old verdict until it is imported again.

- **«Me encanta» with no similar recipe** (`me_encanta`): today every «Me encanta» (rating 5) is on a recipe we have; the source is reserved for when the household profile records loved dishes without a recipe.
