# Recipes · El catálogo y la página de receta

> Parte de [Recipes](./recipes.md) (la portada lista todas las partes): el catálogo público, orden, retiradas y borradores, la página de receta, vistas previas de enlaces, colecciones, «con lo que tengo», «este mes», de dónde viene una receta y las bases de batch cooking.

## User Capabilities

- **Catálogo público — `/recipes` without an account** (2026-10-15): the recipe list has one URL for everyone. Signed out, `/recipes` is the public catalogue: public chrome (PublicNavbar «Recetas» + Footer, no sidebar, bottom bar or Mimo; content on the public grid `public-container`, so no left gap on desktop), an editorial header (eyebrow «Catálogo Mimoia», h1 «Recetas con *criterio*.», «Las recetas de Mimoia: de temporada, con sus tiempos reales y paso a paso. Ábrelas y cocínalas sin cuenta.»), then the same search, chip row, «De temporada» hero and card grid as the app. Only the **generic browsing filters** are there: search, «De temporada», «En 30 min», the intent chips (Listas en 15 min, Cenas rápidas, Para picar, Sin gluten), Desayuno/Comida/Cena/Merienda and «Más filtros» (Temporada, Tiempo total, Comida). Hidden signed out, because they need an account: «Nueva receta», «Mis recetas» and «Selección Mimoia» (everything shown is Mimoia's catalogue; the sheet's «Recetas» group too), «Con lo que tengo», household tags. The API answers an anonymous `GET /recipes` with system recipes only (`authorId IS NULL`). Cards open `/recipes/[id]`; the list ends with the waitlist block «Para hacerlas tuyas · Apúntate y Mimoia te plantea la semana con ellas.» → «Únete a la lista de espera» (`/?ref=recetas#lista-de-espera`, `CatalogueWaitlistCta` — see [Waitlist](./waitlist.md)). Signed in, `/recipes` is unchanged (below). **`/recipes-ona` is a permanent redirect (308) to `/recipes`**, query kept (`next.config.ts`); its old page is gone. In the sitemap. Tests: `e2e/app-signed-out.spec.ts` (390×844 + 1440×900).
- **Catalogue order** (PRO-140, signed in and out, `services/recipeCatalogOrder.ts`): `GET /recipes` lists first the recipes **more households have in favourites** (the count is never shown and filters nothing); on a tie (today, all at 0) **Miguel's featured list** `FEATURED_RECIPES` in `@ona/shared`, in its order (by id; on staging or a fresh database by name, accents and case ignored); then the rest, oldest first. The page doesn't re-sort; the seasonal «De temporada» hero is still picked apart. To change the featured list, edit `FEATURED_RECIPES`, not the sorting.
- **Retired recipes** (PRO-140): a catalogue recipe with `retirada` in `internal_tags` (`RETIRED_RECIPE_TAG`) is not listed by `GET /recipes` (signed in or out), the menu never picks it (generator and every automatic swap, via `loadMatchableRecipes`) and Mimo's suggestions don't offer it; whoever has it in a menu, favourites or a cookbook still sees it and opens it by id. Example: «Crema de zanahoria», retired for «Crema de zanahoria con pollo, aguacate y granada».
- **Catalogue drafts** (PRO-154, [Catalogue import](./catalog-import.md)): a catalogue recipe brought in by the batch import is `draft` (`recipes.status`) until its batch is published — not listed, 404 by link (except for an admin, who reviews the sample that way), never picked by the menu or offered by Mimo. Its house photo is made while it's a draft, and it isn't published until it has one (so nobody sees a catalogue recipe without its photo).
- **Names** (PRO-140): no «Gipsy» in catalogue names and accents put back. The seed uses the new names (`Fideuá`, `Pastela vegetariana`, `Tacos caseros`, `Pollo agridulce`, `Curry cremoso de tofu`, `Albóndigas express`, `Cocido madrileño`…); `CATALOG_RENAMES` (`services/recipeRenames.ts`) lists old → new: `db:seed` renames an old row before upserting (no duplicate), and the boot-time source-link backfill finds a renamed recipe's original link under its old Notion name, so «Ver fuente» stays. Tests: `recipeCatalogOrder.test.ts`, `recipeCatalogOrder.smoke.ts` (real API + DB), `e2e/recipe-catalog-order.spec.ts` (390×844 + 1440×900).
- **Página de receta — one page for everyone** (2026-10-15): `/recipes/[id]` is the only recipe detail. For a catalogue recipe it opens **without an account**, complete: photo, eyebrow, ingredients with the servings stepper, steps, Equipo/Alérgenos/Temporada/Etiquetas, nutrition, the recipe's own notes, **Compartir** and **Empezar a cocinar** (cook mode `/recipes/[id]/cook` works signed out too, without Mimo's hands-free). Signed out the page wears the **public chrome** (fixed PublicNavbar on top, Footer at the bottom; no sidebar, bottom tab bar, Mimo button, install sheet or health-consent gate; photo, sticky tabs and the desktop sticky photo start below the navbar) and ends with the **waitlist block** «¿Te gusta? Guarda *X* y plantéate la semana con ella.» → «Únete a la lista de espera» (`/?ref=receta#lista-de-espera`, `RecipeWaitlistCta`). Everything personal (favorite, Añadir al menú, Cocinada, recetario, *Tus notas*, galería, editar, Añadir a mis recetas, ingredient overrides) is behind `user &&`; back links fall to `/recipes` (public too). Signed in, nothing changes (app shell). A **private recipe opened signed out** (the API answers 404, never 403) shows «Esta receta es privada.» with «Entrar» (`/login?next=/recipes/<id>`) and «Ver el catálogo» (`/recipes`). **Signed in, a 404** (deleted recipe, someone else's, or a broken link) shows «Esta receta ya no está.» with «Ir al menú» (`/menu`) (PRO-181). The chrome is chosen in the root layout by `RootShell` from the route (`signedOutChrome` in `lib/routeAccess.ts`, which uses `publicRecipeRoute` from `lib/recipeShell.ts`) and the session; while the session (localStorage) resolves on first load these routes paint an empty cream page, so the wrong chrome never flashes. `/recipes/new` and `/recipes/[id]/edit` need an account (signed out → `/login?next=…`, see [Auth](./auth.md)). The old public detail **`/recipes-ona/[id]` is a permanent redirect (308) to `/recipes/[id]`**, query kept (`next.config.ts`). Tests: `e2e/recipe-public-page.spec.ts` (390×844 + 1440×900), `recipePublicPage.test.ts` (unit)
- **Back from a recipe** (2026-11-05): the photo's back button goes back in history when the recipe was opened inside the app, else to its fallback. A recipe opened from the menu carries `?desde=menu` (`menuRecipeHref` in `lib/menuReturn.ts`: dish titles and rows, «Ver receta», the week grid): its fallback is `/menu` and on desktop the pill reads **«Menú»** and goes back (before it was always «Recetas» → the catalogue), landing on the week and day the menu showed (`?week=` + `?day=`, see [Menus](./menus.md)). Any other recipe keeps «Recetas» / `/recipes`. Tests: `e2e/menu-back-from-recipe.spec.ts` (390×844 + 1440×900), `menuReturn.test.ts` (unit).
- **Link previews** for `/recipes/[id]`: a server `app/recipes/[id]/layout.tsx` fetches the recipe from the API **without a token** (2.5 s timeout, cached 5 min, fails soft) and sets title «<nombre> · Mimoia», a description («Receta para 4 personas · 45 min · 9 ingredientes. Ingredientes, pasos y modo cocina en Mimoia, …»), Open Graph (article, absolute photo URL — a relative `/images/recipes/…` is resolved against `https://mimoia.com`), `twitter: summary_large_image` and `canonical` `https://mimoia.com/recipes/<id>` (`recipeMetadata` in `lib/recipeMetadata.ts`). A private or missing recipe gets generic, non-indexed metadata («Receta · Mimoia», `robots: noindex`), so a link never reveals a private recipe. The root layout skips its default `<title>`/description on `/recipes/<id>/…` (`isRecipeSegment`) so the tags aren't duplicated
- Logged-in users browse the catalog at `/recipes` ("D · Luz y foto", 2026-10-08): header "Recetas" + ink "+" (**Nueva receta**), one search field (placeholder "Busca una receta" — search matches names only), **one chip row**, then photo cards (2-column masonry on mobile). A card is the photo with only a **time pill** (total time, else prep time; omitted when unknown) and the Fraunces title — nothing else: no season badge, no ownership badge, no "Selección Mimoia" mark (nearly every recipe is curated, so it would be noise; "Selección Mimoia" is only a chip). Recipes without a photo show a quiet pot placeholder (no stock photo). **Other users' recipes are never returned** — every authenticated caller (including admins) sees only system recipes + their own. When nothing is searched or filtered, a **"De temporada" hero** tops the grid (mobile: one full-bleed 220 px photo; `lg+`: two 290 px cards) with a paper caption "De temporada · N min" + title: an in-season recipe with a photo (curated seasonal ones first, then curated all-year), rotating daily (`pickFeaturedRecipes`). A small "N recetas" line (+ "Quitar filtros" when anything is on) sits above the grid. When the user has copied a system recipe via "Añadir a mis recetas", the catalogue listing **suppresses the original** from this user's view (via the `copied_from_recipe_id` back-reference) so the same dish doesn't appear twice
- **Colecciones** (PRO-374, signed in and out): when nothing is searched or filtered, a row **«Colecciones»** sits under the «De temporada» hero: Cocina's editorial collections («Vuelta al cole», «Invitados en casa», «Otoño»…), newest first, each a card with the first recipe's photo, the title and «N recetas» (scrolls sideways on mobile). No row when there are none. A card opens **`/recipes/coleccion/<slug>`**: «‹ Recetas», eyebrow «Colección», title, subtitle, «N recetas» and the recipes in Cocina's order with the catalogue card (`CatalogGrid`); open without an account (public chrome and the waitlist block at the end, `isCollectionRoute` in `lib/recipeShell.ts`); an unknown or unpublished collection shows «Esta colección ya no está.» Only published, not retired catalogue recipes show; a collection left with none leaves the row. Never a collection by health (§6): see [Catalogue import](./catalog-import.md) → «Colecciones» for how Cocina uploads them. Tests: `catalogCollections.test.ts`, `e2e/recipe-collections.spec.ts`.
- Users can copy a system (or another user's) recipe into their own catalog with the **"Añadir a mis recetas"** button on the recipe detail (visible only when `recipe.authorId !== user.id`). The copy is independent — editing it doesn't affect the original — and inherits ingredients, steps, times, nutrition cache and image. The new row gets `internalTags: ['copied-from-catalog']` and `sourceType: 'manual'`
- Users can search recipes by name (case-insensitive substring match)
- Users filter from the **chip row** (toggle buttons with `aria-pressed`; none active = "Todas"): **De temporada** (current season), **En 30 min** (total time ≤ 30), the **intent shortcuts** (PRO-376, from FuturApp; signed in and out) — **Listas en 15 min** (the 15-min time filter, same as «Hasta 15 min» in the sheet), **Cenas rápidas** (dinner and ≤ 30 min), **Para picar** (`course = 'starter'` or the tag `picoteo`) and **Sin gluten** (no `gluten` in the card's `allergens` and no allergen doubt — the import's internal tag `alergenos:duda`, sent on the card only as `allergenDoubt: boolean`); several on = all must match; rules `isQuickDinner` / `isNibbles` / `isGlutenFree` in `@ona/shared` (`catalogSeason.test.ts`, `e2e/recipe-intent-chips.spec.ts`); «Para llevar en táper» waits for PRO-372 —, **Desayuno / Comida / Cena / Merienda**, **Selección Mimoia** (system recipes only — was the "Catálogo Mimoia" tab) and **Mis recetas** (the caller's own — asked to the API with `?mine=1` since PRO-299: filtering the first 100 catalogue cards left out the newest copies, which the catalogue order puts last, so a household saw 7 of its 8 recipes). Scope persists in `localStorage.ona.recipes.scope`. **Más filtros** (button inside the search on mobile, link at the end of the chip row at `lg+`) opens the advanced filters dialog (bottom sheet on mobile, centred panel at `md+`; Escape / backdrop close it): Temporada (any season, "Ahora: otoño" hint), Tiempo total (15/30/60 min), Comida, Recetas (Todas / Selección Mimoia / Mis recetas), Etiquetas propias, "Limpiar todo" and "Ver N recetas". Active filters with no chip (another season, 15/60 min, tags) show as a count badge on the button. Season, time and scope filter client-side (`filterCatalogRecipes` in `@ona/shared`): a season matches recipes listing it **or with no seasons**, a time filter uses the total time and drops recipes of unknown time; meal, search and tags are server-side
- **Con lo que tengo** (PRO-31, 2026-10-11) is the first chip of the row: it opens a paper panel under the chips («¿Qué tienes? Elige hasta 3 ingredientes. Sal, aceite, agua, pimienta y harina se dan por hechos.») with a search over the ingredient catalogue (`GET /ingredients?search=`, exact name first, no «crear ingrediente») and the picked ones as removable ink chips. With ≥1 picked the grid shows `GET /recipes/with-what-i-have` instead of the plain listing: visible recipes (catalogue + household's own; a copied original stays hidden) that use at least one of them, ranked by how many they use, then by how little is missing, then by name. Each card adds a line «Te falta: puerro, cebolla» or «No te falta nada más» — never the basics nor optional ingredients. A picked ingredient also matches other catalogue rows whose name contains it as a word («Huevo» → «Huevos camperos»). Recipes that break the user's allergies, diet or dislikes never appear (same rules as Mimo's `suggest_recipes`). The other chips still narrow the results client-side (search and meal too). No hero while it's on; turning it off or «Quitar filtros» brings the catalogue back. Mimo runs the same search (`cook_with_what_i_have`, see [Advisor](./advisor.md))
- **Este mes** (PRO-375, 2026-10-29; idea from the FuturApp review, OK of Miguel 2026-10-27): above the hero and the grid, signed in and out, a row titled «Este mes» with the **fruits and vegetables of the month** as icons (emoji in a 56 px paper circle + name; scrolls on mobile, wraps at `lg+`; `group` «Productos del mes», each a toggle with `aria-pressed`). Only products that **at least 3 published catalogue recipes use** show, most used first (`GET /recipes/seasonal-produce?month=`, the browser's month). Tapping one filters the catalogue by that ingredient (`GET /recipes?ingredient=<nombre>`): an ink chip «🎃 Calabaza ✕» («Quitar Calabaza») appears next to the title and takes it off, as does tapping the product again or «Quitar filtros»; no hero while it's on. The other chips still apply. Hidden while «Con lo que tengo» is on (turning that on drops the product). The months and emojis come from the **calendario de producto** `SEASONAL_PRODUCE` in `@ona/shared` (~65 products of Spain, months 1–12, `produceInSeason(month)`), not from `ingredients.seasons` (35 seed rows, by season). An ingredient counts as a product when its normalised name (no accents, lower case) has one of the product's terms as a whole word, plurals too, and none of its exclusions: «Setas» takes champiñón, boletus, níscalo…; «Calabaza» never takes «calabacín»; «vinagre de manzana» is not manzana. More visual than the «De temporada» chip, which stays. Tests: `seasonalProduce.test.ts`, `seasonalProduce.smoke.ts`, `e2e/seasonal-produce.spec.ts`
- Users can open a recipe detail view at `/recipes/[id]` (layout "D · Luz y foto", 2026-10-08). **Mobile (< lg)**: 390 px hero photo (without a photo, the same neutral `cream-deep` pot placeholder as the cards — never a stock photo of another dish, see [recipe-images.md](./recipe-images.md); back · share · favorite on 44 px paper circles; for the author/admin, a pencil at the photo's bottom-right that opens `/recipes/[id]/edit`, PRO-03), a cream sheet with an eyebrow (meals · category · total time · difficulty) + title (+ the credit line «Receta de la Yaya» / «Inspirada en…», "Rinde…", "Ver fuente", "Cocinada N× · última…" when present), then a tablist: **Ingredientes** (default — "Para [− N raciones +]" stepper, the ingredient list, "Editar ingredientes", the **"Para hacer la compra"** card for the author/admin when some row can't go to the shopping list or a shop order as written — see [recipe-quality.md](./recipe-quality.md) → Shoppability; the same card sits above the ingredients box on `/recipes/[id]/edit`, and writing an amount in a line "al gusto" there («1 jengibre fresco», «20 g de jengibre fresco») makes it "ud"/"g" so the card goes away after saving, PRO-90 — then Equipo, Alérgenos, Temporada, Etiquetas) · **Pasos · N** (prep/cook timeline + numbered steps) · **Nutrición** (only when nutrition is cached, or when it is incomplete — then without figures, PRO-176) · **Notas** ("Cocinada" + "Añadir a recetario", the recipe's own notes / sustituciones / conservación, *Tus notas*, Galería, "Editar receta" + "Regenerar imagen" for author/admin, "Añadir a mis recetas"). Tabs stick to the top while scrolling, follow ←/→/Home/End, and the open tab lives in the URL hash (`#pasos`, `#notas`…) so a reload or link reopens it. A sticky bottom action bar (84 px) holds the single "Empezar a cocinar"; the bottom tab bar is hidden on this route. **Desktop (lg+)**: sticky rounded photo on the left ("← Recetas" pill; author/admin also get the edit pencil top-right), long-scroll right column — eyebrow, 48 px title, meta (time · difficulty · kcal por ración), action row (Empezar a cocinar · share · favorite), Ingredientes (stepper + 2-column list), Preparación (big terracotta 01, 02…), Equipo/Alérgenos/Temporada/Etiquetas, Nutrición, Notas. **"Añadir al menú"** (PRO-04): a calendar button beside "Empezar a cocinar" in the mobile action bar and a pill in the desktop action row open a sheet (`AddToMenuSheet`) with the 7 days of this week, each with Comida / Cena. A free slot shows "Libre" and takes the recipe (`POST /menu/:menuId/day/:day/meal/:meal { recipeId }` when the day lacks the slot, `PUT` when it exists empty); an occupied slot shows its dish and swaps it for this recipe (`PUT … { recipeId }`); one that already holds the recipe is disabled; a locked one is replaced like any other and stays locked (PRO-1175: the lock only keeps a meal when the week is redone). After placing it: "«X» está en tu menú: domingo, cena" + "Ver mi menú". No menu this week → "Aún no tienes menú esta semana" + "Ir a mi menú". Logic in `apps/web/src/lib/addToMenu.ts` (unit test `addToMenuSlots.test.ts`, e2e `recipe-add-to-menu.spec.ts`)
- Users can change the number of diners (1–12) with the "Para [− N raciones +]" stepper on the detail; ingredient quantities scale on the fly and "Empezar a cocinar" carries `?servings=N`
- A **coeliac household** (restrictions with gluten, profile or memory) sees «Elige embutido sin gluten» above the ingredients of a recipe with a cured meat whose gluten depends on the brand (chorizo, morcilla, butifarra, salchicha, foie, jamón de york…; PRO-196), and «Elige <ingredient> sin gluten» once per blended spice or stock in it («Elige chili en polvo sin gluten», «Elige caldo de verduras sin gluten»; chili en polvo, curry, ras el hanout, caldo, cubito, fumet…; PRO-1063, list in [Nutrition](./nutrition.md)). `GET /recipes/:id` sends them as `dietNotices` only to that signed-in household (`DietNotices.tsx`, `data-testid="diet-notices"`); Mimo's `get_recipe_details` adds the same notice. Legal reviews the wording before it goes public
- **The detail says what is estimated** (PRO-32): when the servings were guessed by the importer (`servingsConfidence: 'estimated'` — the source didn't say), a discreet «Estimado» tag sits next to the «Para [− N raciones +]» stepper (testid `servings-estimated`; tooltip «La receta original no decía para cuántas personas; lo hemos calculado.»). Set by imports (URL, WhatsApp, Mimo, and the photo extractor on `/recipes/new` until the user types the number); saving the edit form stores `explicit` (the author has reviewed it); an ingredient stored with quantity 0 (imported without an amount) reads «cantidad sin indicar», never «0 g» (`formatQuantity` in `apps/web/src/lib/recipeView.ts`, also in cook mode and step chips; `pizca`/`al gusto` keep their text); the Nutrición block (`NutritionCard` on `/recipes/[id]`) ends with «Estimación a partir de los ingredientes; no es consejo médico.»; and «Ver fuente» under the title links to the original when there is a `sourceUrl`. Tests: `recipeEstimated.test.ts` (unit), `e2e/recipe-estimated.spec.ts` (390×844)
- **The ficha says where a catalogue recipe comes from** (D-067, 2026-10-20): right under the title, one line in Cormorant italic, `ink-muted`, 18 px (21 px at `lg+`; testid `recipe-credit`) — «Receta de la Yaya», «Inspirada en una receta de Ferran Adrià, «La comida de la familia»»; a long one wraps. When the recipe also has `sourceUrl`, the credit is a link to the original (new tab, `rel="noopener noreferrer"`, same look, underlined on hover/tap; PRO-1075) and «Ver fuente» stays below; without `sourceUrl` it is plain text. It is `sourceCredit` on `GET /recipes/:id`, read from `recipes.catalog_source` by `catalogSourceCredit` (`services/catalogImport.ts`): the import's `credit` as written; without one, a book of Miguel's reads «Inspirada en <libro>»; Cocina's recipes and every other recipe get `null` and no line. Nothing else of `catalog_source` (file, batch, audit notes) leaves the API. A personal copy («Añadir a mis recetas») has no line: the copy doesn't carry `catalog_source`. How the credit gets in: [Catalogue import](./catalog-import.md). Tests: `catalogImport.test.ts`, `catalogImport.smoke.ts`, `e2e/recipe-credit.spec.ts` (390×844)
- **Bases de batch cooking** (PRO-373, fase 1): a **base** is a catalogue recipe tagged `base` (`BASE_RECIPE_TAG`, `isBaseRecipe` in `@ona/shared`; public or internal tag) — sofrito, legumbre aliñada, verduras asadas — cooked one day for several dishes of the week. It is listed in `/recipes` and opens like any recipe, but **the menu never picks it as a dish** (`loadMatchableRecipes` drops it, so the generator, slot swaps and Mimo's suggestions skip it; `buildRandomMenu` drops it too). A dish links to the bases it uses in `recipe_bases` (migration `0109_recipe_bases`, only adds: `recipe_id` → `recipes` on delete cascade, `base_recipe_id` → `recipes` on delete **restrict**, `servings_used` = servings of the base for one batch of the dish). The ficha says so under the title (and the credit): «Usa: *Sofrito* (2 raciones)», each base a link to its page (testid `recipe-bases`; `bases: [{ id, name, servings }]` on `GET /recipes/:id`, only the bases the reader may open — a draft base only for an admin). The shopping list buys each base once for every dish that uses it ([Shopping](./shopping.md) → Bases). Links come from Cocina's import (`bases` in the file, [Catalogue import](./catalog-import.md)); there's no editor for them yet. Fase 2 (another task): the «Batch cooking» style plans a day to cook the bases. Tests: `recipeBases.test.ts`, `e2e/recipe-bases.spec.ts` (390×844)
- Users can favorite/unfavorite a recipe (toggle via heart button); the heart turns at once (optimistic, flipped back if the call fails) and remembers: `GET /recipes/:id` and `GET /recipes` carry the signed-in reader's own `is_favorite` (until 2026-10-21 they didn't, so the saved heart looked dead — «el botón me gusta no funciona o no cambia de color»). The toggle is queued offline and replays on reconnect — see [PWA](./pwa.md)
- Users can create their own recipes (form at `/recipes/new`)
